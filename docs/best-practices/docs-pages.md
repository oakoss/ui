# Docs pages

How to write a component page in `apps/docs/content/docs/components`. Each entry is a rule and its reason. `button.mdx` is the reference page.

- **Sections in this order:** a preview, then `## Installation`, `## Usage`, `## Examples`, `## Accessibility` and `## API`. Visitors and agents find the same thing in the same place on every page; `build.test.ts` checks the order.
- **Front matter names the registry item and the React Aria page** (`item: button`, `reactAria: https://react-aria.adobe.com/Button`). The links under the title come from them: Source (the item's component file on GitHub) and React Aria.
- **The preview is `<ComponentPreview name="<demo>">`** wrapping the demo from `src/components/demos`. A remark plugin turns it into Preview/Code tabs at build time, with the demo file's source in the Code tab, so the code also reaches the `.md` and llms.txt output (search indexes no code blocks). Demos draw no border of their own; the preview frame does.
- **Installation is `<ComponentInstall item="<name>" />`.** The plugin builds the CLI command and the manual steps (packages, then every file the item and its registry dependencies install) from `packages/ui/registry.json`, so they can't drift from what `shadcn add` installs. The page shows each file's source; the `.md` and llms.txt output list the files with GitHub links instead, since the shared files would otherwise repeat on every page. Package-manager tabs remember the visitor's choice across pages.
- **Every example is live:** one sentence naming the prop it shows, then a `<ComponentPreview>` of its own demo (`src/components/demos/<component>-<example>.tsx`). The Code tab shows that file, so the code a visitor copies is the code that rendered. Demos are self-contained: one that needs state (form errors, a pending flag) keeps it locally.
- **Accessibility says what React Aria provides, what the component adds, and the keys.** Take keyboard behavior and data attributes from React Aria's source or docs, not memory. Link the WAI-ARIA pattern where one exists. Say "React Aria adds no keys" when the native element's behavior stands.
- **API is one block per part:** `### <Part>`, a line naming what it extends with a link, then `#### Props` (own props only, via `auto-type-table`, then "Also accepts…"), `#### Data attributes` and `#### CSS variables` as hand-written tables. Parts with no props of their own share one table.
- **A demo that renders an icon needs an `IconResolverContext` provider,** as Storybook's preview has. Resolve only the names `icons.tsx` uses rather than importing a library's namespace, which would ship every icon to the site.
