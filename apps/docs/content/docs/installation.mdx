oakoss/ui installs with the [shadcn CLI](https://ui.shadcn.com/docs/cli) into a
React project with Tailwind CSS v4. This site hosts the registry, and these
docs describe its latest release.

## Set up the project

Run this once. The `base` item installs the theme, `color-scheme` and the
reduced-motion styles and `lucide-react`, and in a new project sets Lucide as
the icon library.

<Tabs defaultValue="new">
  <TabsList>
    <TabsTrigger value="new">New project</TabsTrigger>
    <TabsTrigger value="existing">Existing project</TabsTrigger>
  </TabsList>
  <TabsContent value="new">

```npm
npx shadcn@latest init https://ui.oakoss.dev/r/base.json
```

This creates `components.json` with the `@oakoss` registry the other commands
use.

  </TabsContent>
  <TabsContent value="existing">

Add the registry to `components.json`:

```json title="components.json"
{ "registries": { "@oakoss": "https://ui.oakoss.dev/r/{name}.json" } }
```

Then add the base item:

```npm
npx shadcn@latest add @oakoss/base
```

This leaves the rest of `components.json` as it is, so components use the icon
library it already names: Lucide, Tabler, HugeIcons, Phosphor or Remix Icon.
For a library other than Lucide, install its package if the project lacks it:
`@tabler/icons-react`, `@hugeicons/react` with `@hugeicons/core-free-icons`,
`@phosphor-icons/react` or `@remixicon/react`.

  </TabsContent>
</Tabs>

Icons that render as empty squares mean `components.json` names no icon
library. Set `"iconLibrary": "lucide"` (or another of the five, with its
package installed) and add the component again.

Give your app's root element `isolation: isolate` (the `isolate` class). Dialogs
and popovers render at the end of `<body>` on the `--z-*` scale, and the root's
own stacking context keeps z-indexes inside the app from competing with them.

## Pick a theme family

The theme starts on Zinc. To use another family, add its item after `base`:

```npm
npx shadcn@latest add @oakoss/theme-mauve
```

The families are `zinc`, `neutral`, `stone`, `mauve`, `olive`, `mist`,
`taupe` and `catppuccin`. Each item sets the family's colors in light and
dark. Adding components keeps the family; adding `base` or `theme` again
resets the colors to Zinc.

Catppuccin uses Latte in light mode and Mocha in dark. For its other dark
flavors, add `theme-catppuccin-frappe` or `theme-catppuccin-macchiato`
instead. Its scales are generated from Catppuccin's colors, keeping each
published color at the step nearest its lightness.

To pick a primary color and corner radius as well, use the theme panel (the
palette button in the sidebar). It restyles this site's component previews
and gives the command that installs the same theme.

[Color Tokens](/docs/theming/tokens) lists every color each family sets, and
[Token Names](/docs/theming/token-names) explains how the names are built.

## Switch themes at runtime

To let users switch families and primary colors while the app runs, add the
`themes` item after `base`. In a project set up with another theme instead,
add it without `base`: it keeps that theme's values and adds only the tokens
the theme lacks.

```npm
npx shadcn@latest add @oakoss/themes
```

It installs `styles/themes.css` (177 KB, 15 KB gzipped) in `src/`, or at the
project root when there's no `src/`, and adds `@import "./styles/themes.css";`
to your stylesheet. The import is relative to the stylesheet, so it suits a
Vite app's `src/index.css`. Elsewhere, such as Next.js's `app/globals.css` or
React Router's `app/app.css`, point it at the installed file
(`../styles/themes.css`); the build fails until you do.

Then set `data-family` and `data-primary` on `<html>` or on any element,
alongside the `dark` class:

```html
<html data-family="catppuccin" data-primary="blue" class="dark"></html>
```

- Pick a primary the family offers; [Color Tokens](/docs/theming/tokens)
  lists them. A family's own version of a color, such as Catppuccin's blue,
  applies only when `data-primary` sits on the same element as `data-family`.
- The theme's selectors outrank `:root` and `.dark`, so a class that sets a
  theme color on the same element loses to them.
- Adding the item again asks before replacing a `themes.css` you've edited,
  and leaves it alone without a terminal; pass `--overwrite` to replace it.

## Add components

```npm
npx shadcn@latest add @oakoss/button
```

Each page lists its own command. The files land in your project, so you can
edit them freely.

## Pin a release

`/r/` always serves the latest release. To stay on one, point the registry at
its folder, `/v<version>/r/`, such as v0.5.0's:

```json title="components.json"
{ "registries": { "@oakoss": "https://ui.oakoss.dev/v0.5.0/r/{name}.json" } }
```

Every item and its dependencies then come from that release, until you change
the version. The [changelog](https://github.com/oakoss/ui/blob/main/packages/ui/CHANGELOG.md)
lists what each release changed.

To try a component before it's released, add it from the repository's `main`
branch:

```npm
npx shadcn@latest add oakoss/ui/button
```

Its dependencies come from `main` too. The CLI asks before replacing shared
files your release installed, such as `lib/cx.ts`, and a component from `main`
may need the newer ones; pass `--overwrite` to take them all.
